### 结论
- 根因修复准确：连接同步现在会在处理远端软删除后重读本地连接列表，后续同步计划不再拿着已删除的旧快照继续算冲突。
- 语义对齐正确：远端删连接时，如果本地确实存在未同步更新，会保留本地并按既定“更新优先”语义重传；如果本地没有更新，则直接删除本地，不再冒出伪冲突。
- 时间基线修复到位：连接从云端回写时改为保留云端秒级 `updated_at` / `last_synced_at`，避免“刚同步完又被误判成本地修改”。
- 远端恢复闭环完整：同步服务器列表页和详情页都已支持恢复软删除记录，仍沿用版本号做并发保护。
- 边界说明充分：工作区恢复提示里明确写出了“只恢复工作区记录本身，不自动重新关联此前解绑的子连接”。
