## 项目上下文摘要（应用窗口圆角预览）
生成时间：2026-03-26 20:31:04 +0800

### 1. 相似实现分析
- **实现1**: `crates/ui/src/window_border.rs:84`
  - 模式：窗口边框和阴影全部在 `WindowBorder::render(...)` 里统一处理。
  - 可复用：边框路径、系统装饰路径判断、四边按 `tiling` 条件裁切。
  - 需注意：之前只有顶部角逻辑，且半径为 0。

- **实现2**: `crates/ui/src/theme/mod.rs:218`
  - 模式：项目主题已经定义统一圆角半径 `radius` 和 `radius_lg`。
  - 可复用：窗口圆角直接复用 `cx.theme().radius_lg`，避免写死魔法数。
  - 需注意：窗口圆角应和其他大块容器风格保持一致。

- **实现3**: `crates/ui/src/styled.rs:186`
  - 模式：组件支持 `.rounded(...)` 和按角单独设置圆角。
  - 可复用：系统装饰路径可直接整块 `.rounded(...)`，客户端边框路径按四角条件单独设置。
  - 需注意：圆角内容如果不裁剪，子内容可能越界。

### 2. 项目约定
- **命名约定**: 继续使用局部变量表达视觉参数，不新增新的全局设置项。
- **文件组织**: 窗口装饰仍只改 `crates/ui/src/window_border.rs`。
- **代码风格**: 公共层一次修改，主窗口和弹窗统一继承。

### 3. 可复用组件清单
- `cx.theme().radius_lg`
- `.rounded(...)`
- `.rounded_tl(...) / .rounded_tr(...) / .rounded_bl(...) / .rounded_br(...)`
- `.overflow_hidden()`

### 4. 测试策略
- **验证方式**: `cargo fmt --all` + `cargo check -p gpui-component -p main`
- **人工验证建议**: 实际打开应用看四角是否圆润、内容是否被正确裁切

### 5. 技术选型理由
- **为什么用这个方案**: 用户只是想“再加点圆角效果”，最小且一致的方案就是接入主题现有圆角半径。
- **优势**: 风格统一，不需要新增配置。
- **风险**: 需要肉眼确认圆角强度是否合适。
