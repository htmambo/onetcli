### 结论
- 恢复链路已核对：恢复 SSH 会话最终仍然调用 `open_ssh_terminal(...)` 和 `setup_terminal_view(...)`，没有发现恢复路径绕开终端设置同步的证据。
- 根因进一步收敛到平台层：Windows DirectWrite 对空 `FontFeatures` 会落入空 Typography，这会影响所有依赖默认字体特性的文本，而不只是一开始修过的终端 helper。
- 修复策略合理：一方面保留终端层对 `liga/clig/calt` 的显式控制，另一方面在 Windows 平台层为默认字体特性显式补齐三项默认值，同时统一 `disable_ligatures()` 的三标签关闭语义。
- 自动化验证仍受阻：`cargo test -p gpui --lib direct_write::tests -- --nocapture` 因网络沙箱无法访问 `static.crates.io` 而失败，当前只能完成格式化与静态链路审查。
- 残余风险可控：仍需在 Windows 上重点确认“恢复 SSH”和“新开 SSH”是否都恢复连字，并确认使用的字体本身支持编程连字。
