# Glass Window Design

**Goal:** 让 OnetCli 主窗口切换为平台原生玻璃背景，并让主应用、列表、表格、侧栏、弹窗等高频数据区域统一进入半透明视觉体系。

## 方案比较

### 方案 A：只改窗口背景

- 优点：改动最小
- 缺点：应用内部仍大量使用不透明背景，视觉上仍然像实心窗口

### 方案 B：逐页面逐组件手工改造

- 优点：可控性最高
- 缺点：涉及面过大，维护成本高，容易遗漏

### 方案 C：平台原生背景 + 全局主题表面 token 玻璃化 + 少量局部去重

- 优点：覆盖面大、改动集中、和现有主题体系兼容
- 缺点：仍需处理少数重复铺底导致的透明度叠加

**采用：方案 C。**

## 设计决策

- 主窗口按平台启用系统背景材质：
  - macOS：`Blurred`
  - Windows：`MicaAltBackdrop`
  - Linux：优先 `Blurred`，Deepin/DDE 保留安全回退
- 在主题层统一调整 `background`、`list`、`table`、`sidebar`、`popover`、`title_bar` 等表面色的 alpha，而不是在业务页面大面积逐个修改。
- 主应用根容器去掉重复铺底，避免半透明背景叠加后变得过实。
- 编辑器高亮主题保留原有配色，只把 `editor.background` 和 `editor.active_line.background` 调成半透明，保证数据密集区一致性。

## 风险

- 某些 Linux 组合窗口管理器不支持真实 blur，只会退化成透明。
- 主题 token 全局半透明后，个别依赖高对比底色的区域可能需要后续微调。

## 验证

- 编译 `main` crate，确认主题和窗口配置改动通过。
- 检查主窗口、标题栏、侧栏、表格和编辑器是否都进入统一玻璃视觉。
