# 首页手动排序设计

生成时间：2026-03-26 22:13:40 +0800

## 目标
为首页连接列表新增“手动排序”模式。用户可以通过鼠标拖拽调整工作区显示顺序，以及同一工作区内连接的显示顺序；排序结果需要在本地持久化，并通过现有云同步体系同步到远端和其他设备。

## 范围
- 首页排序字段新增第四种：手动排序。
- 工作区之间支持拖拽重排。
- 同一工作区内连接支持拖拽重排。
- 未分配区内部连接支持拖拽重排。
- 本地数据库持久化顺序。
- 云同步携带顺序字段。

不在本次范围内：
- 通过拖拽改变连接所属工作区。
- 把连接拖入其他工作区。
- 对工作区内部做更细粒度分栏或嵌套拖拽。

## 现状
首页当前的排序完全依赖 `ConnectionListSortField` 与 `ConnectionListSortOrder`：
- 工作区排序由 `compare_workspaces(...)` 决定。
- 连接排序由 `compare_connections(...)` 决定。
- 工作区与连接实体本身没有“显示顺序”字段。
- 云同步明文数据结构也没有顺序信息。

因此，仅做 UI 拖拽无法满足需求，必须同时扩展数据模型、存储层与同步层。

## 方案
采用“实体内置顺序字段”方案，而不是单独新建首页排序表。

### 数据模型
- `Workspace` 新增 `sort_order: Option<i32>` 或 `i32`
- `StoredConnection` 新增 `sort_order: Option<i32>` 或 `i32`

推荐使用非空整型并在 migration 中统一回填，这样比较逻辑和仓库更新都更简单。

### 排序模式
`ConnectionListSortField` 新增 `Manual`。

排序行为：
- `Name` / `CreatedAt` / `UpdatedAt`
  - 保持现有行为
- `Manual`
  - 工作区：按 `workspace.sort_order ASC`
  - 工作区内连接：按 `connection.sort_order ASC`
  - 未分配连接：按 `connection.sort_order ASC`
  - 未分配工作区 section 仍固定显示在所有具名工作区之后

手动排序模式下，升降序按钮不再有实际意义，建议禁用或隐藏。

### 本地存储
新增 migration：
- `workspaces` 表新增 `sort_order INTEGER NOT NULL DEFAULT 0`
- `connections` 表新增 `sort_order INTEGER NOT NULL DEFAULT 0`

为防止升级后列表顺序突然变化，migration 中按“当前默认显示顺序”回填：
- 工作区按 `updated_at DESC, id ASC`
- 每个工作区内连接按 `updated_at DESC, id ASC`
- 未分配连接按 `updated_at DESC, id ASC`

这样用户升级后看到的初始顺序与升级前尽量一致。

### 仓库层
需要扩展：
- 模型读写映射，补上 `sort_order`
- `insert` / `update` / `insert_from_cloud` / `update_from_cloud`
- 新增批量更新顺序的方法，分别针对：
  - 工作区顺序
  - 某个工作区内连接顺序
  - 未分配连接顺序

批量更新时应一次事务提交，避免中途写入造成顺序断裂。

### 同步
扩展明文结构：
- `WorkspacePlainData.sort_order`
- `ConnectionPlainData.sort_order`

同步行为：
- 本地上传：把最新顺序带上
- 云端下载：恢复顺序
- 远端覆盖本地：顺序视为实体字段的一部分，一起更新

冲突策略保持当前通用同步语义：实体级“更新时间较新者覆盖”。

### 首页拖拽交互
只在 `Manual` 模式启用拖拽。

#### 工作区拖拽
- 可拖动工作区 header
- 只能在工作区 section 之间重排
- 不允许拖到未分配连接区内部

#### 连接拖拽
- 可拖动连接卡片或列表项
- 只能在同一工作区内部重排
- 未分配区的连接只能在未分配区内部重排
- 跨工作区拖放直接忽略，不改变 `workspace_id`

#### 交互反馈
- 拖拽目标显示插入位置高亮
- 放下后立即更新当前页顺序
- 异步写库成功后保持
- 写库失败时回滚内存顺序并提示错误

## 实现顺序
1. 先扩展模型与 migration。
2. 再扩展 repository 与同步明文结构。
3. 再补首页排序逻辑，把 `Manual` 并入现有排序体系。
4. 最后接拖拽 UI 和顺序持久化。

这样可以把“能正确读写并同步顺序”先做稳，再叠加交互。

## 验证策略
- 模型 / 仓库测试：
  - 新字段可正确读写
  - 批量顺序更新只影响目标组
- migration 测试：
  - 旧数据升级后顺序稳定
- 同步测试：
  - 顺序字段可被加密上传、解密下载、云端回写
- 首页排序测试：
  - `Manual` 模式下比较函数按 `sort_order`
- 交互验证：
  - 手动模式下工作区可拖拽
  - 同一工作区内连接可拖拽
  - 跨工作区拖放无效

## 风险与取舍
- 这是一个跨多层的功能，工程量大于普通 UI 优化。
- 但由于明确不支持跨工作区归属变更，复杂度和回归风险都明显降低。
- 最大收益是：排序结果与实体同步数据一体化，后续维护简单。

## 决策结论
采用“实体新增 `sort_order` + 排序字段新增 `Manual` + 仅支持同层级重排”的方案。
